# dbmock

为 `insight` 构造一个中国中小型综合电商平台规模的两年期 Doris 数仓

## 数据目标

- 数据截止时间取任务实际开始执行时的 `Asia/Shanghai` 业务日期
- 默认开始日期为截止日期向前两个自然年，首尾日期均包含
- 商品目录使用国内公开电商页面的真实商品数据
- 平台画像为综合型电商，经营结构偏 3C、服饰和家居，不强行把真实商品目录调整为品类均匀分布
- 用户、流量、交易、营销和库存按真实业务分布生成
- 会话、搜索、加购、订单、支付、履约、退款和库存使用同一条业务时间线
- 跨日和跨月事件到实际发生日期后才写入 Doris，截止时刻保留未完成业务
- 日期维度通过 `chinese-calendar` 使用国务院公布的法定节假日和调休工作日安排，运行区间超出依赖支持年份时直接报错，不按周末规则猜测
- 历史事实的入仓时间根据业务发生时间和处理延迟生成，不统一使用任务执行时间
- 外部页面没有公开的字段不伪装成采集值，平台内部成本和库存等字段使用明确的业务生成模型

## 当前数据规模

真实商品目录包含：

- 5,000 个 SPU
- 31,554 个真实 SKU
- 522 个类目

- 12 个一级类目

商品全部来自苏宁公开商品页，每个 SPU 包含 1～40 个源站 SKU，平均 6.31 个 SKU

## 真实数据与生成数据边界

真实采集字段包括：

- 商品标题、品牌、店铺、来源类目和公开商品参数
- SPU 与 SKU 关系、SKU 规格、售价、划线价和图片
- 外部商品 ID、外部 SKU ID、来源链接和采集时间

平台标准化字段包括：

- 内部 SPU、SKU、品牌、类目、商家和店铺业务 ID
- 平台三级类目和品牌名称归一结果

业务生成字段包括：

- 用户、用户标签和用户等级变化
- 商品上架时间、历史价格轨迹和标准成本
- 活动窗口、优惠券窗口和适用范围
- 会话、浏览、搜索、点击、收藏和加购
- 订单、支付、物流、退款和评价
- 初始库存、预占、释放、出库、退货入库和采购补货

这些字段不是外部平台采集记录，但必须满足真实业务的时间顺序、金额关系、状态流转和库存连续性

## 生成架构

数仓包含 45 张业务表

生成过程分为两层批次：

- 业务月份批次负责时间演化和状态继承
- 每 250,000 行的 PyArrow Parquet Stream Load 批次负责物理写入 Doris
- 每个月结束后按表使用 4 个工作线程并发写入，单个表内部仍保持顺序

Parquet 使用 Snappy 压缩并开启 Doris 严格模式。并发只改变物理装载方式，不改变业务时间演化、随机种子、表粒度或跨表关联

完整生成流程：

```text
初始化日期、地区、用户和真实商品维度
  ↓
初始化具有独立活动窗口和适用范围的营销规则
  ↓
按业务月份推进
  ↓
按天生成价格事件
  ↓
会话 → 浏览 → 搜索 → 点击 → 收藏／购物车 → 订单
  ↓
库存原子预占或分配失败 → 条件支付方式 → 支付失败重试
  ↓
拆包履约 → 签收 → 退款或评价
  ↓
未来事件进入待处理队列，到实际业务日期后写入
  ↓
采购下单 → 1～7 天在途 → 到货入库，以及退货入库
  ↓
将当月库存事件写入 Doris
  ↓
Doris 按集合计算生成库存日快照
  ↓
完成当月并继续生成下个月
```

商品不会同时在第一天上架。平台初期保留一部分存量商品，其余商品在两年内逐步上架，库存日快照只覆盖当日已经上架的 SKU

SKU 新品标识根据上架日期计算，热销状态根据订单日汇总计算，库存预警阈值保存在 SKU 拉链维度。这些属性不再重复保存为逐 SKU 的运营日快照

商品历史价格从内部上架价格逐步演化，在采集日期附近与真实采集价格衔接。标准成本根据稳定的品类毛利区间生成，因此订单成本、库存成本和毛利分析不再全部为 0

初始库存按 SKU 生成 1～12 件低周转覆盖量，不再固定为每个 SKU 100,000 件。生成期间根据预计销量、可用库存、安全库存和在途库存创建采购单，采购量包含供应波动并在 2～9 天后到货。缺货取消只能由实际库存分配失败触发，不再按固定概率生成

用户注册时间覆盖存量期和两年业务期。用户等级、VIP、生命周期状态和标签在月末根据滚动 30／90／180 天活跃、累计订单、消费、退款及品类偏好生成新的 SCD2 版本，不使用累计会话数阻止用户进入沉默或流失状态

会话长度、跳出、路径、搜索词、无结果、改写、点击、渠道、操作系统和版本使用条件分布。购物车支持加入、数量变更、删除、清空、跨会话保留和放弃，收藏支持收藏与取消。支付方式由终端、客单价和年龄共同决定，支付及退款均包含失败和重试，评价覆盖 1～5 星、无文本和追评

公开页面无法验证的店铺评分不生成伪造历史，因此已删除空的店铺评分快照表。仓库落在真实行政区划内，具体物流园地址明确为脱敏生成值。SKU 使用稳定履约仓，转化商品按收货省份所属服务大区选取，订单出库仓、包裹发货仓和库存变更仓保持一致

## 失败处理

生成过程不保存检查点，也不支持中断恢复。任务启动时要求 45 张业务表均为空，任意阶段失败后应执行 `make init_db` 重建数据库，再重新运行生成任务

跨月库存、用户和交易状态只在本次进程内继承，不写入本地文件或 Doris 技术表

## 本地性能

2026-08-07 在本项目本地 Docker Doris 环境完成生成模型版本 4 基准：

- 七天 smoke 约 25 秒
- 两年全量耗时约 17 分 20 秒
- 全量覆盖 731 个业务日、25 个自然月批次和 45 张表
- 总行数 24,568,329，其中库存日快照 15,705,893 行
- 生成 4,000,000 条页面访问、600,000 条搜索、1,250,359 个会话、204,963 条购物车事件和 100,000 条订单明细
- 全量质量报告状态为 `passed`，`failures=0`、`warnings=0`
- 购物车会话下单转化率 42.55%，购物车变更事件率 7.85%，取消收藏率 10.59%
- 缺货取消率 1.46%，零可售库存 SKU 日占比 0.076%，在途库存 SKU 日占比 0.894%
- 总优惠率 9.74%，月度转化率变异系数 5.49%，沉默或流失用户占比 6.16%

该结果包含基础维度初始化、月度生成、Stream Load、Doris 集合快照和最终质量扫描。实际耗时受 CPU、磁盘、Docker 内存和 Doris 现有负载影响

## 审计时间

- 事务事实根据事件时间模拟分钟级处理延迟
- 日快照根据每日期末时点模拟小时级处理延迟
- 维度根据生效时间或来源更新时间生成入仓时间
- 所有业务时间和入仓时间均不晚于任务实际开始时刻
- `load_batch_id` 使用逻辑运行 ID 和业务月份
- 跨月事实使用实际事件发生月份的 `load_batch_id`，不使用订单创建月份

## 环境要求

- Python 3.12 及以上版本
- `uv`
- Apache Doris 4.0 及以上版本
- dbmock 主机可以访问 Doris FE 的 `9030`、`8030` 端口和 BE 的 `8040` 端口

初始化项目环境：

```bash
cd dbmock
cp .env.example .env
uv sync
```

数据库连接从 `.env` 读取且没有默认值：

```dotenv
DB_HOST="127.0.0.1"
DB_PORT=9030
DB_USER="root"
DB_PASSWORD=
DB_NAME="ecommerce"
```

Stream Load 的 FE HTTP 端口在 `src/settings.py` 中固定为 `8030`

## 使用流程

### 准备真实商品目录

新环境执行完整采集：

```bash
uv run python -m collection
```

只校验现有目录：

```bash
uv run python -m collection --validate-only
```

强制清空采集断点并重新采集：

```bash
uv run python -m collection --force-download
```

`data` 不进入 Git，完整目录包括：

```text
data/
├── manifest.json
├── brands.json
├── categories.json
├── shops.json
├── spus.jsonl
├── skus.jsonl
├── lineage.jsonl
├── quality_report.json
├── geo_regions.json
├── logistics_companies.json
├── payment_types.json
└── source/
    ├── suning_products.jsonl
    ├── suning_rejections.jsonl
    └── raw/*.html.gz
```

### 初始化 Doris

```bash
make init_db
```

该命令会永久删除并重建 `.env` 中 `DB_NAME` 指定的数据库，然后创建 45 张业务表

### 生成数据

完整生成：

```bash
make generate
```

`make generate` 只允许对空数据库执行。生成失败或需要重新生成时，必须先运行 `make init_db`

七天小规模验证：

```bash
make init_db
make smoke
```

只加载公共维度和商品维度：

```bash
make init_db
uv run main.py --dimensions-only
```

只校验已有数据：

```bash
make validate
```

## 质量校验

完整任务结束后检查：

- 必填业务表非空以及未知维度成员完整
- SCD2 生效区间不重叠且只有一个当前版本
- SPU、SKU、品牌、类目和店铺引用完整
- 每条订单明细可以追溯到来源会话和同会话加购事件
- 页面、搜索、点击、收藏、购物车和下单时间全部位于来源会话边界内
- 购物车存在加入、数量变更、删除、清空和未下单放弃路径
- 订单活动优惠和优惠券金额分摊一致
- 优惠券分摊用券时间与用户券 `USED` 生命周期事件一致
- 支付金额与订单明细支付分摊一致
- 包裹重量和运费与包裹商品分摊一致
- 已发货或已完成订单明细的正向配送数量与购买数量一致
- 退款金额不超过对应订单实付金额
- SKU 价格事件变更前后价格连续
- 库存事件变更前后数量连续且不会出现负库存
- 缺货取消存在库存分配失败证据，且同一订单不存在成功预占
- 库存日快照等于当日库存事件处理后的期末状态
- 会话页面访问数和搜索数与事件明细一致
- 事实业务日期、事件时间和入仓时间顺序正确
- 订单、支付、配送和退款状态时间严格递增
- 事实业务月份与 `load_batch_id` 月份一致
- 历史数据入仓时间不会全部集中在任务执行日期
- 跳出率、无结果率、搜索点击率、支付成功率、支付重试率和退款率落入校准区间
- 购物车转化、购物车变更、取消收藏、库存暴露、总优惠、月度转化波动和用户生命周期落入校准区间
- 退款驳回／撤销、退款打款失败、负向评价和评价文本唯一率落入校准区间
- 新增注册占比、用户标签数、自营订单贡献和近期订单终态占比落入阻断阈值

校验结果写入 `data/quality_report.json`，包含样本量、阈值、指标状态、表行数、商品清洗统计、商品字段血缘和生成模型字段血缘。报告属于本地验收产物，不写入 Doris
